# Self-Hosting ugo

This guide walks you through deploying ugo on your own server using [Once](https://github.com/basecamp/once). The pre-built Docker image is published to [GHCR on every tagged release](https://github.com/fdocr/ugo/pkgs/container/ugo), so you don't need to build anything yourself.

## Prerequisites

- A server (Ubuntu 22.04+ recommended) with SSH access
- A domain name with DNS pointed at your server's IP address

No local toolchain is required. Once handles everything on the server.

## 1. Install Once and ugo

SSH into your server and run:

```bash
curl https://get.once.com | sh
```

Once will install Docker if needed, register its background service, and launch the interactive setup. When prompted:

1. Choose **"Enter a Docker image path"**
2. Enter: `ghcr.io/fdocr/ugo`
3. Enter the hostname you want to use (e.g. `links.example.com`)
  - Make sure the domain's DNS is already pointed at your server's IP address, otherwise the setup will fail

Once will pull the image, boot the application, and provision an SSL certificate via Let's Encrypt.

## 2. Complete the setup wizard

Visit your domain in a browser. You'll see the setup wizard where you'll configure:

- **Setup code**: Find this in the container logs. Run `docker ps` to get the container ID, then `docker logs <container_id>` and look for the line `SETUP CODE: <code>`.
- **App name** and **domain**
- **Admin email** and **password**
- **SMTP settings** (optional, for email notifications)

After completing the wizard, your ugo instance is ready to use.

## Automatic updates

Once automatically checks for new image versions and applies updates with zero downtime. The `latest` tag on GHCR is updated with every release, so your instance stays current without any manual intervention.

## Backups

Once handles backups automatically. ugo includes SQLite backup hooks that create consistent database snapshots without pausing the application. Configure your backup location in the Once dashboard under your app's settings.

To manually trigger a backup:

```bash
once backup
```

## Useful commands

```bash
once                    # Open the Once dashboard (TUI)
once list               # List installed applications
once update             # Manually check for updates
once backup             # Trigger a backup
docker ps               # Find the container ID
docker logs -f <id>     # Tail application logs
docker exec -it <id> bin/rails console   # Open a Rails console
docker exec -it <id> bin/rails dbconsole # Open a database console
```

## How it works

ugo is a standard Rails 8 application using SQLite for storage. All persistent data lives under `/rails/storage/`, which Once mounts as a persistent volume. Cryptographic keys (Active Record Encryption) are auto-generated on first boot and stored on the same volume.

No environment variables need to be configured manually. Once provides `SECRET_KEY_BASE` automatically, and the application generates everything else it needs on first boot.

## Environment variables reference

Most configuration is handled through the setup wizard and admin panel. The following optional environment variables can be set if running Docker directly (outside of Once):

| Variable | Default | Description |
|---|---|---|
| `SECRET_KEY_BASE` | Auto-generated by Once | Session signing and CSRF protection |
| `ACTIVE_RECORD_ENCRYPTION_PRIMARY_KEY` | Auto-generated on first boot | Encrypts sensitive fields at rest |
| `ACTIVE_RECORD_ENCRYPTION_DETERMINISTIC_KEY` | Auto-generated on first boot | Enables deterministic encryption lookups |
| `ACTIVE_RECORD_ENCRYPTION_KEY_DERIVATION_SALT` | Auto-generated on first boot | Salt for key derivation |
| `WEB_CONCURRENCY` | `1` | Puma worker **processes** (uses `preload_app!` when greater than 1; see concurrency section) |
| `RAILS_MAX_THREADS` | `3` | Puma **threads** per worker (also sizes the DB pool floor; see below) |
| `JOB_CONCURRENCY` | `1` | Solid Queue worker **processes** ([`config/queue.yml`](config/queue.yml) `processes`) |
| `SOLID_QUEUE_THREADS` | `3` | Solid Queue **threads** per worker process ([`config/queue.yml`](config/queue.yml) `threads`) |
| `SOLID_QUEUE_IN_PUMA` | enabled | Set to `false` to disable the Solid Queue Puma plugin (advanced; use `bin/jobs` separately) |
| `DB_POOL` | _(auto)_ | Optional override for Active Record pool size per process (default: max of `RAILS_MAX_THREADS` and `SOLID_QUEUE_THREADS` + 2) |
| `RAILS_LOG_LEVEL` | `info` | Log verbosity (`debug`, `info`, `warn`, `error`) |
| `HONEYBADGER_API_KEY` | _(unset)_ | [Honeybadger](https://www.honeybadger.io/) error-tracking API key; reporting is disabled when unset (see [Error tracking](#error-tracking-honeybadger)) |
| `TRUSTED_PROXIES_EXTRA` | _(unset)_ | Optional extra proxy CIDRs beyond the baked Cloudflare list (advanced) |
| `CLOUDFLARE_PROXIED` | _(unset)_ | Set to `true` only if `CF-Connecting-IP` should be trusted without a Cloudflare edge IP in the proxy chain (rare) |
| `CLOUDFLARE_TURNSTILE_SITE_KEY` | _(unset)_ | Cloudflare Turnstile site key for sign-up bot protection (managed ugo.cr) |
| `CLOUDFLARE_TURNSTILE_SECRET_KEY` | _(unset)_ | Turnstile secret key; sign-up protection disabled when unset |

## Concurrency (Once Environment)

Set these in Once: **`s`** → **`v`** (Environment) → add keys → **Done** (Once redeploys).

**Defaults** suit a small VPS (1 Puma process, 3 threads, 1 Solid Queue worker). On a larger machine (e.g. 4 CPU / 8 GB), you might use:

```text
WEB_CONCURRENCY=3
RAILS_MAX_THREADS=5
JOB_CONCURRENCY=2
SOLID_QUEUE_THREADS=3
```

That yields roughly **3 × 5 = 15** concurrent web threads and **2 × 3 = 6** job threads. Tune down if you see high memory use or SQLite lock contention.

### Connection pool

Active Record’s `pool` is **per Ruby process**, not shared across the machine. You do **not** set `pool` to `WEB_CONCURRENCY × RAILS_MAX_THREADS`. Each Puma worker and each Solid Queue worker process gets its own pool; the size defaults to the larger of `RAILS_MAX_THREADS` and `SOLID_QUEUE_THREADS` + 2 (worker and heartbeat threads per [Solid Queue](https://github.com/rails/solid_queue#configuration)). Set `DB_POOL` only if you need a higher explicit ceiling.

### Verify after changing concurrency

```bash
docker exec <container_id> printenv WEB_CONCURRENCY RAILS_MAX_THREADS JOB_CONCURRENCY SOLID_QUEUE_THREADS
```

## Error tracking (Honeybadger)

Error tracking via [Honeybadger](https://www.honeybadger.io/) is optional and disabled by default. It is configured **solely** through the `HONEYBADGER_API_KEY` environment variable — there is no admin-panel setting. Errors are only reported in the production environment, and the integration disables itself automatically when the variable is unset.

Add the variable in Once: **`s`** (Settings) → **`v`** (Environment) → add a row with **Key** `HONEYBADGER_API_KEY` and **Value** = your project API key → **Done** (Once redeploys). The new key takes effect once the container restarts.

Verify it is set:

```bash
docker exec <container_id> printenv HONEYBADGER_API_KEY
```

## Cloudflare (orange cloud) and trusted proxies

Skip this section if DNS points **directly** at your server without a proxied CDN (grey cloud / no Cloudflare proxy).

When traffic flows **Browser → Cloudflare → Once → ugo**, the Docker image already includes current Cloudflare proxy CIDRs in `config/cloudflare_cidrs.txt`. Release builds (manual tags and GeoLite2 rebuilds) refresh that file from Cloudflare before the image is built. No long environment variable is required.

**Cloudflare SSL/TLS mode** must be **Full (strict)** when using the orange cloud ([Once README](https://github.com/basecamp/once#using-once-to-install-and-configure-applications)).

### Firewall the origin (recommended)

Restrict HTTP/HTTPS to [Cloudflare IP ranges](https://www.cloudflare.com/ips-v4) so `CF-Connecting-IP` and `X-Forwarded-For` cannot be spoofed by bypassing Cloudflare.

### Verify analytics

Open a short link from a normal browser and confirm geography in analytics looks reasonable (not every visit from the same Cloudflare datacenter).

Optional: set `DEBUG_CLIENT_IP=true` in Once Environment temporarily and inspect logs for a `[client_ip]` line showing `source=cf_connecting_ip`.

### Advanced environment variables

| Variable | When to set |
|---|---|
| `CLOUDFLARE_PROXIED=true` | Only if analytics IPs are still wrong and logs show Cloudflare headers without a Cloudflare edge IP in the proxy chain |
| `TRUSTED_PROXIES_EXTRA` | Additional proxy CIDRs beyond Cloudflare (comma-separated) |

To refresh the committed fallback file locally: `bin/rails trusted_proxies:cloudflare`

### CDN cache notes

At Cloudflare, bypass cache for short-link redirects (`GET /:slug`), deep link bounces (`GET /r`), `/up`, `/webhooks/*`, and authenticated app pages so redirects and webhooks stay dynamic. You may cache `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json` (see [Deep linking](deep-linking.md)).
